## CLI v0.37.1

- fix(core)!, feat(cli)!: one-shot processes exit; add ark iam works out of the box (#190)

* fix(core)!: a process with health checks exits when its runners finish

The readiness monitor was waited for like a user runner and only returned
on cancellation, so application.Run never returned for a one-shot process
with any check registered. Only user runners now decide the lifetime: when
they have all returned the runner context is canceled, the monitor drains
and Run returns. With no user runners the process still waits for its
context or Shutdown.

BREAKING CHANGE: a process that registers checks now exits after its last
runner returns instead of waiting for shutdown.

* feat(iam)!: mount provider routes relative to the router prefix

Register hard-coded "`/auth/<name>`" for the provider login, callback, nonce
and native routes and for the connect redirect, so mounting the identity
routes under a prefix such as /auth produced `/auth/auth/<name>` and a
redirect to a route that did not exist. The provider routes are now
"`/<name>`" relative to the router Register is called on, and the connect
handler redirects to the login route beside it, reading the mount prefix
from the request path before "/connections/".

BREAKING CHANGE: with routes.Group("/", identity.Register) the provider
routes move from `/auth/<name>` to `/<name>`; mount at /auth to keep the old
paths and register provider callback URLs with the mount prefix.

* feat(cli)!: add ark iam works out of the box; sign-in providers move to add ark oauth

add ark iam now leaves a project that starts with no manual steps:
- migrations run at server startup: a Migrator and a Migrate provider (Startup
  callback over Migrator.Up, safe for replicas) are written and Migrate is
  listed before IAMRouter; an existing Migrator gets IAM.Migrations inserted;
- .env gets DATABASE_URL=file:app.db (when Database is written), the reset and
  verification page URLs and each client's redirect URL, derived from
  HTTP_ADDR, never overwriting a variable and never writing secrets or paths;
- the identity routes are mounted under /auth;
- next steps shrink to the key files (with their arkoren key command) and
  make run.

add ark oauth takes one or more of google, github, microsoft, apple and oidc,
inserts identity.Provider into an existing iam.go, and add ark iam wires the
clients it finds.

The generated-project test now starts the server and checks POST /auth/login
(422) and GET /auth/sessions (401), and that a migrate process exits 0.

BREAKING CHANGE: add ark iam --with no longer accepts google and github; use
add ark oauth. The generated identity routes are mounted under /auth instead of
the root, and provider routes need ark/iam with relative provider paths. (c318ff801359346b0c84fb7fa126c3c8d9f64951)
